# User manual

The Maple Ridge Onboarding Assistant answers new-hire questions from five HR documents: orientation, benefits, required forms, leave, and workplace conduct. The documents are fictional and were written for this course project.

## For new employees

### Ask a question

1. Open the assistant in your browser (when running locally: http://127.0.0.1:8000).
2. Type your question in the **Your question** box, or choose one of the example topics to fill in a sample question.
3. Click **Ask**. While the assistant works, the button is turned off so the question is not sent twice.
4. Read the answer. Below it are the **sources**: the original passages from the HR documents that the answer is based on. Check the wording there before you act on an answer.

Questions can be up to 1,000 characters. Plain, specific questions work best, for example "What time should I arrive on my first day?"

### What the results mean

| You see | What it means | What to do |
| --- | --- | --- |
| An answer with sources | The documents cover your question. | Read the quoted passages to confirm the details. |
| "The available documents do not answer this question. Please contact HR." | The assistant did not find a passage that answers you, so it will not guess. | Contact HR, or try rewording with the words an HR document might use (for example, "paid time off" rather than "vacation"). |
| A message about personal information | Your question looked like it contained an email address, phone number, or Social Security number. | Remove it and ask again. The assistant never needs these details. |
| "Please use 1,000 characters or fewer." | The question is too long. | Shorten it. |
| "We couldn't get an answer. Please try again." | A temporary problem on the server or with the AI service. | Wait a moment and try again. If it keeps happening, tell the person who runs the assistant. |

### Privacy

- Do not enter personal or confidential information, such as health, pregnancy, or family details. Your question is sent to an outside AI service to produce the answer.
- The server never writes your question or the answer to its logs. It records only the type of result and how long it took.

### Known limits

- The assistant only knows the five HR documents. Questions about anything else get the HR message.
- Search matches words. A question worded very differently from the documents can miss, even when the answer exists. In our test set, "Can I take a vacation during my first month on the job?" is one example, because the policy says "paid time off."
- Answers are generated by an AI model and can be wrong. The sources shown are the check.

## For the person running the assistant

### Start it

Follow the setup in the project `README.md`, then run:

```bash
python -m uvicorn app.main:app --reload
```

### Choose the AI provider

Settings live in a local `.env` file, which is never committed to Git.

| Setting | Values |
| --- | --- |
| `AI_PROVIDER` | `fake` (test mode, no key needed), `anthropic`, or `openai` |
| `AI_MODEL` | The model name from the provider's documentation |
| `AI_API_KEY` | Your key from the provider (keep it private) |

Restart the server after changing `.env`. If the provider, model, or key is missing or wrong, the page shows "We couldn't get an answer" and the server log says the provider is not configured, or gives the provider's HTTP status.

In test mode, answers start with "[Test mode…]" and quote the top search result. This checks search and the page, not the quality of a real AI answer.

### Update the HR documents

1. Edit or add a JSON file in `data/documents/`. Each file has a `document_id`, a `document_title`, and a list of `passages`, each with a `passage_id`, a `heading`, and `passage_text`.
2. Rebuild the search database:

   ```bash
   python -m scripts.build_index
   ```

3. Run the checks (`python -m pytest -q` and `python -m scripts.run_test_questions`) before sharing the change.

### Check that it works

| Check | Command | Passing result |
| --- | --- | --- |
| Automated tests | `python -m pytest -q` | All tests pass |
| 20-question search check | `python -m scripts.run_test_questions` | At least 14 of 16 answerable questions find the right passage |
| End-to-end with a real provider | `python -m scripts.run_end_to_end` (server running) | At least 14 of 16 answered with the right citation, 4 of 4 unsupported questions get HR guidance |
| Timing | `python -m scripts.benchmark` | Median well under 10 ms for our own code |
